三个代理客户端与 OpenVPN，如何在多网卡环境中稳定共存

让国内流量走有线、代理节点走手机热点、公司资源走 OpenVPN。本文使用脱敏占位符，可安全作为公开文章底稿。

一句话方案

只运行一个代理客户端，统一本地端口，默认关闭 TUN；用规则决定 DIRECT/PROXY，再用 Windows 主机路由固定代理节点的物理出口。

分流原理图

代理规则负责分类；Windows 路由负责选择实际网卡。两层缺一不可。

三个客户端的统一配置

v2rayN

  • 系统代理：自动/PAC
  • 本地端口：7897
  • 绕过大陆
  • TUN 关闭

Clash Verge

  • 系统代理：开启
  • Mixed Port：7897
  • Rule 模式
  • TUN 关闭

悠兔

  • 系统代理：开启
  • Mixed Port：7897
  • Rule 模式
  • TUN 关闭
三个客户端可以使用相同端口，但不能同时启动。同一个本地端口同一时间只能由一个进程监听。

固定代理节点出口

route -p add <NODE_IP> mask 255.255.255.255 <HOTSPOT_GATEWAY> if <INTERFACE_INDEX> metric 1
route print <NODE_IP>

这条主机路由比默认路由更具体。即使有线网络或 OpenVPN 改变默认出口，代理节点仍可固定经手机热点连接。切换节点或共享方式后必须重新确认参数。

Codex CLI

$env:ALL_PROXY = 'http://127.0.0.1:7897'

排错顺序

  1. 确认只有一个代理客户端运行。
  2. 验证 127.0.0.1:7897 正在监听。
  3. 检查当前节点 IP 的静态路由。
  4. 检查 OpenVPN 是否下发公司路由和 DNS。
  5. 检查公司域名是否命中 DIRECT。
  6. 最后再调整 IPv6、Fake-IP、TUN 等复杂选项。
