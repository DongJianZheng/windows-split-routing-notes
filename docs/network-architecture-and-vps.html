Windows 多网卡分流与 VPS 出口架构

一份可长期维护的实践笔记：国内直连、OpenAI/Codex/GitHub 走 VPS、其他境外网站走悠兔，以及手机 Wi‑Fi 节点路由。

一、最终架构

规则决定“哪个出口”；Windows 路由决定“哪个物理网卡”。

二、为什么这样设计

稳定

VPS 作为 OpenAI、Codex 和 GitHub 的固定出口，减少节点频繁变化导致的登录验证和连接变化。

兼容

只开启系统代理、不启用 TUN，避免接管 OpenVPN、微信、ToDesk 等不应代理的程序。

可切换

悠兔订阅自动更新，VPS 和规则放在覆写模板中，订阅更新不会覆盖自定义配置。

四、VPS 部署操作

当前电脑使用的是 VPS 的 VLESS + WebSocket + TLS 出口。以下是新 VPS 的通用部署流程；真实域名、UUID 和证书不要写入公开文章或 GitHub。

1. 准备 VPS

# Debian/Ubuntu
sudo apt update && sudo apt install -y curl unzip ufw
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

2. 准备域名和 TLS

将域名 A/AAAA 记录指向 VPS。生产环境使用 443/TLS；证书可以由 Caddy/Nginx 管理，也可以由 sing-box 直接管理。不要把管理面板暴露在公网。

3. 安装代理核心

# 推荐使用官方 sing-box 安装方式，并固定版本
sudo mkdir -p /etc/sing-box
sudo install -m 700 -d /var/lib/sing-box
# 将经过审计的 sing-box 二进制放入 /usr/local/bin/sing-box
# 将配置写入 /etc/sing-box/config.json
sudo systemctl enable --now sing-box
sudo systemctl status sing-box

4. 配置要点

{
  "inbounds": [{
    "type": "vless",
    "listen": "127.0.0.1",
    "listen_port": 10000,
    "users": [{"uuid": "<RANDOM-UUID>"}],
    "transport": {"type": "ws", "path": "/<RANDOM-PATH>"},
    "tls": {"enabled": true, "certificate_path": "/etc/ssl/fullchain.pem", "key_path": "/etc/ssl/privkey.pem"}
  }],
  "outbounds": [{"type": "direct"}]
}

上面是结构示意，不要直接复制到生产环境。实际配置应按当前 sing-box 版本校验，并使用随机 UUID、随机 WS 路径和最小权限运行。

5. Windows 端导入

在 v2rayN 或 Clash Verge 中添加 VPS 节点，确认服务器、端口 443、UUID、TLS SNI、WebSocket 路径完全一致。然后只把该节点放入 VPS-OpenAI-Git 代理组。

五、日常切换流程

  1. 启动 Clash Verge，确认系统代理开启、规则模式开启、TUN 关闭。
  2. VPS 组选择 VPS-OpenAI-Git，悠兔组选择自动选择或固定节点。
  3. 连接手机 Wi‑Fi 后运行 Wi‑Fi 路由脚本；切换悠兔节点后再次运行。
  4. 启动或重启浏览器、桌面 Codex，确保重新读取 7897。
  5. OpenVPN 保持无代理（Proxy=None），公司域名和内网由 OpenVPN 自己处理。
cd 'D:\工作工具\windows-split-routing-notes'
powershell -ExecutionPolicy Bypass -File .\scripts\set-youtu-wifi-route.ps1

六、现在安全吗？

结论：从配置结构看，当前方案属于“可控、风险中等”的个人网络方案；但不能承诺绝对安全或绝对不封号。安全性取决于 VPS、代理订阅、系统权限和密钥管理。
风险判断建议
VPS 出口 IP数据中心 IP 可能触发验证码或风控保持固定出口，避免频繁切换，不要共享给他人
订阅泄露订阅链接通常等同于账号凭据不要提交 GitHub、截图或公开文章；泄露后立即重置
VPS 服务暴露开放端口和弱口令会增加攻击面只开放必要端口，SSH 使用密钥，及时更新系统
公司网络错误代理可能导致内网数据外发公司域名、私网、OpenVPN 程序固定 DIRECT
DNS/IPv6 绕过可能导致规则和出口不一致排错阶段关闭 IPv6，使用明确的 DNS 策略
TUN接管范围大，可能影响 OpenVPN 和多网卡路由当前方案保持 TUN 关闭
不要在公开文章中出现真实订阅 URL、UUID、公司域名、内网网段、VPS 登录信息、完整日志或截图。文档中的占位符必须替换后再发布。
